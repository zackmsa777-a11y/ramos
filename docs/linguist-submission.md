## Acceptance gates before opening an upstream PR

1. Verify at least 2,000 `.ramos` files indexed within the last year, excluding
   forks and distributed reasonably across independent owners/repositories.
   Use the current upstream template's
   [search query](https://github.com/search?type=code&q=NOT+is%3Afork+path%3A*.ramos+%22fn%22).
   The API search observation currently supplies no qualifying evidence.
2. Rebase the registration branch on current upstream main and refresh the
   grammar using upstream scripts. Do not hand-edit generated metadata.
3. Run the full tests and CI checks on a complete checkout, including grammar
   compilation and license validation with upstream grammar submodules available.
4. Use the upstream PR template, link the usage search and original sample,
   state MIT licensing, and mark only conditions that are actually satisfied.

Linguist maintainers must then accept and merge the contribution. GitHub staff
must release/deploy Linguist before GitHub.com can label Ramos. Neither publishing
this grammar nor setting a `.gitattributes` override performs those steps.

The implementation is ready to inspect and use locally; meeting adoption policy
is a separate requirement that cannot be replaced by copied files or fake repos.
